# 配装页交互体验记录

日期：2026-09-16。先按玩家实际操作体验，再修复并复测；范围覆盖配装页现有功能。首次检查只覆盖主路径，随后按用户要求扩展到完整功能，并补查用户指出的默认职业、品级、排序、来源联动和自动保存。

## 实际感受

原界面把连续配装拆成多个页面，用户需要反复寻找下一步；同时擅自预选职业、限制品级、写入方案。问题不只是按钮布局，而是页面经常没有按照用户当前意图响应。

修复后的操作原则：先由玩家选择职业，试配保留在内存草稿中，明确保存才写入方案。候选在原位置给出差异和应用动作；搜索与筛选控制显示结果，不自动修改用户条件。

## 逐项检查

| 操作 | 普通用户的预期 | 原来的实际行为／发现 | 修复与复测 |
| --- | --- | --- | --- |
| 第一次进入 | 先选自己的职业 | 直接创建学者方案并保存 | 职业不预选，开始前不创建方案；验证无存储写入 |
| 浏览装备 | 能看到所有品级，再自行筛选 | 自动套用 780–795 等推荐范围 | 浏览默认不限品级，默认不隐藏过时装备 |
| 排序 | 品级和属性都能从高到低或从低到高 | 只有降序 | 两个方向都验证，等值项目保持稳定顺序 |
| 获取途径 | 与正在搜索、筛选的装备一致 | 展示全量来源；初次修正还漏掉搜索词 | 按搜索词、职业、部位、品级及过时开关联动，覆盖所有结果页 |
| 已选来源不再匹配 | 明确没有结果，由我调整条件 | 容易形成难以解释的空列表 | 已选项标记无匹配，保留条件并提供单独清除来源 |
| 保存／打开方案 | 点击保存才写入，打开不改文件 | 每次修改和打开都会写入 | 创建、修改、撤销、打开均不写；明确保存才持久化 |
| 切换方案／新建／导入／离开 | 不应悄悄丢失修改 | 自动保存掩盖了未保存状态 | 保存并继续、不保存继续、取消；保存失败留在当前草稿 |
| 更换职业 | 空草稿可以改职业；有装备时理解后果 | 下拉选择直接增加一份新方案 | 空草稿保留身份；已有装备的新职业使用新草稿，离开未保存方案先处理修改 |
| 新建、复制、切回 | 当前职业和原方案可辨认 | 新建总是回到学者，“另存”实际复制 | 新建沿用当前职业；复制明确命名，副本先为草稿；保存后可切回 |
| 修改方案名 | 删除旧名称后重新输入，不立即报错 | 清空输入立刻触发保存失败 | 完成输入才更新；空名称失焦恢复原值；一次改名对应一次撤销 |
| 等级、品级同步、种族 | 属性随设置变化，同步影响清楚 | 功能存在，散在方案设置 | 已实际切换；同步时镶嵌弹窗说明魔晶石不生效 |
| 连续选择部位 | 配完武器直接继续头部 | 需返回配装页再进入候选 | 宽屏保留当前装备；部位选择器、下一部位、返回配装均走通 |
| 候选比较、取消、应用 | 同时知道替换什么及变化多少 | 比较要离开候选；没有取消预览 | 就地展示原装备、新装备、属性差值与 GCD；取消不改草稿 |
| 预览键盘操作 | 键盘也能确认，迟到计算不恢复取消内容 | Enter 存在，取消路径缺失 | 首次 Enter 预览，再次应用；取消后的迟到结果被丢弃 |
| 搜索、筛选、分页 | 看到空结果后能够直接恢复 | 提示清除但无按钮，筛选层会遮挡操作 | 内联展开、一键复位、范围错误说明、分页回列表顶部 |
| 两枚戒指、食品、药品、专家证 | 各部位都有合理的候选 | 消耗品、专家证沿用装备品级导致空列表 | 学者、刻木匠、采矿工逐部位配置；类别分别保留筛选范围 |
| 直接镶嵌、移除 | 在身上装备旁边操作 | 镶嵌入口藏在换装页 | 装备行直接打开；镶嵌和移除均进入可撤销草稿 |
| 保证孔与禁断 | 每孔只出现合法等级，知道实际属性 | 可选魔晶石多，但看不到单件最终属性 | 五孔制作装实测；新增单件属性与上限展示 |
| 装备锁、镶嵌锁、批量清除 | 两种锁含义不同，清除不伤锁定配置 | 锁按钮文本不明确，空方案也能清除 | 明确镶嵌锁文本；无可清除内容时禁用；已锁镶嵌保留 |
| 自定义属性与换回旧装备 | 能编辑，换回时恢复原配置 | 原有备选配置逻辑需验证 | 实际编辑自定义武器；制作装换出再换回保留五孔及锁定 |
| 撤销、重做 | 能恢复误操作，知道是否仍未保存 | 有历史栈，但写入行为不明确 | 应用、移除、清除、改名可撤销；回到已保存快照恢复已保存状态 |
| 属性、阈值、详细效果、用量 | 看到整套结果与备料数量 | 功能存在，入口分散 | 阈值与效果展开、用量表、其他生产职业工具计数开关均操作 |
| 分享与导入 | 错误码可修正，成功导入不覆盖原方案 | 基本功能存在，但保存副作用隐藏 | 剪贴板分享、非法码、有效码、新草稿导入及原方案保留验证 |
| 保存失败与重试 | 保留修改，成功后错误消失 | 重试成功仍显示失败信息 | 故障注入后重试；保存并离开失败时不执行跳转 |
| 旧草稿恢复失败 | 保留旧数据，有继续工作的入口 | 有保留机制，恢复路径需复核 | 注入损坏旧数据，保留原串，显式选择职业创建新草稿 |
| 战斗优化 | 设置条件，查看结果，再决定应用或另存 | 获取途径全量，参与勾选难以发现 | 真实 Rust 优化，独立计算范围，逐件排除与返回入口 |
| 优化约束、空范围、取消 | 不合法输入有说明，运行能取消 | 错误主要到计算时才显示 | 提前验证 GCD、品级、速度、周数与目标；空范围、恢复、取消均操作 |
| 当前装备优化、信念／直击分配 | 各模式能返回可用结果 | 功能存在，须真实计算确认 | 当前装备、信念／直击、备选分配、应用与另存均调用真实求解器 |
| 生产、采集优化 | 使用当前装备和各自属性目标 | 依赖先选齐工具、装备和消耗品 | 刻木匠与采矿工完整配置后执行真实优化并应用 |
| 全部职业入口 | 切换后显示对应部位 | 原默认行为容易留下大量空方案 | 全部职业入口实际切换；无自动存档 |
| 窄窗口与暗色弹窗 | 不溢出，关闭后返回操作位置 | 暗色弹窗挂在 body，未继承主题 | 1440×900、1024×700、720×520；明暗主题、Escape、遮罩、Tab 与焦点返回验证 |

## 证据与边界

- 最终交互补充：整行属性与底部留白均可点击选装，镶嵌和锁定互不误触，支持 Enter；阈值表直接展示前一档负数、后一档正数，验证开关与窄窗口布局。

- 图标与食品后续复核：真实新武器图标在镜像返回 404、官方返回 200，浏览器确认自动回退加载成功。验证装备图标、镶嵌与锁定按钮中心和行中心一致，食品无魔晶石列、展示利用率，修正固定表头层级和缩进；截图 `icon-fallback.png`、`centered-equipment.png`、`food-candidates.png`。利用率与图标相关 4 项测试通过。

- 装备名颜色：核对 Asvel 原版 `src/stores/Gear.ts` 的来源优先规则，复用仓内颜色映射。浏览器检查当前装备、候选、选中状态与镶嵌详情；明暗截图为 `.impeccable/review/name-colors-light.png`、`name-colors-dark.png`。同次回归重新验证属性绿色 `+54`、上限截断、同步失效和同屏面板等高。

- 同屏选装复核：保留左装备、右候选；左栏拓宽，左右面板等高并各自滚动。浏览器断言桌面顶部与高度相等、直接点左侧切换右侧部位，检查 1440、1024、720px 无页面横向溢出。属性加成验证 `+54`、上限截断与同步失效，截图为 `materia-bonus.png`、`candidates-wide-*.png`。

- 后续配装布局复核：武器独行并留 24px 间距；左列头、身、手、脚、腿，右列耳环、项链、手镯、双戒指。每件装备在页面内直接显示生效属性，消耗品显示实际加成。浏览器验证 1440、1024、720px 布局、完整属性展示、镶嵌与同步后的数值更新；截图为 `.impeccable/review/layout-*.png`。

- 最终 `npm test` 143 项通过；生产构建、ESLint、所改前端文件的 Prettier 检查均通过。
- 28 组浏览器场景通过，日志在 `.impeccable/review/flows.json`、`defaults-flows.json`、`extra-flows.json`。浏览器使用临时存储适配器，不触碰已有用户方案。
- 页面加载真实装备目录并执行真实 TS 属性计算；优化通过临时适配器调用仓库现有 Rust `solve` 程序，不伪造优化结果。
- 浏览器取消测试验证 UI 状态和迟到结果处理，适配器终止计算进程；不把它当作完整 Tauri 原子取消信号验证。
- 原生 `gearing_storage.rs` 原文件在独立测试包中通过实际文件读写、覆盖、路径限制与损坏记录保留测试。

- Impeccable 引擎缺失，未声称自动设计检测通过。验证使用实际浏览器操作和截图。
