# 配装迁入与维护规范

当前架构以 [整体重构规范](gearing-refactor.md) 为准。
最初迁移中“保留 MST、前端轻量计算、按品级加载 JSON”的规定已被替代。

## 功能与归属

- 一次性迁入后独立维护；保留装备、魔晶石、食物、属性、阈值、同步、自定义武器、三类优化和分享。
- 不使用 submodule、本地包链接、独立 Vite 工程或整站嵌入。
- 不把其他业务迁移到配装的状态管理方式，不新增全仓 Store 框架。
- 页面入口在 `src/pages/GearingPage.tsx`，编辑器在 `src/features/gearing/editor/`。
- 配装使用原生 CSS 和共享设计 token，不保留 SCSS、Sass 或原网页控件。
- 来源、许可证及署名保留在 `licenses/ffxiv-gearing/`；重写代码不改变复用部分的许可。
- 配装图标只保留一个 SVG sprite；该文件沿用用户批准的提交行数例外。

## 数据更新

```bash
npm run gearing:data:update -- --check
npm run gearing:data:update
```

- 来源是固定提交的原始游戏表与物品链接索引，不读取 ffxiv-gearing 应用工程。
- 装备数据不调用 XIVAPI sheet 查询 API，也不调用 GitHub REST API。界面仅按生成数据中的图标 ID 使用 XIVAPI asset 端点加载图片。
- 默认解析公开发布记录，然后下载固定提交的 CSV，在内存中转换和校验。
- 职业、魔晶石、具名公式系数及人工来源由本仓 `scripts/gearing/config/` 维护。
- 优化策略在 `optimizer-policy.json` 维护；公共默认值只在生成时合并一次。
- 产物只有静态 `catalog.json` 和带摘要的 `manifest.json`，目录已 gitignore。
- 不提交或缓存原始 CSV、装备 JSON、压缩快照；不保留本地仓库导入入口。
- 目录包含全部历史物品，由 TS 建立索引并本地查询，不再分割装备 JS 文件。
- 更新记录来源固定提交、输入摘要、生成器版本、内容版本和参数版本。
- `--check` 不修改已有产物；下载、校验或安装失败保留上一份完整目录。
- 回退使用匹配的本仓规则与 `--ref <发布提交> --lodestone-ref <提交>`。
- 更新后重启 Tauri 开发环境或重新构建，不实现数据热重载或客户端在线更新。

## 计算与文档

- TS 负责普通属性评估、阈值、用量统计与优化方案编排；Rust 只保留耗时搜索及评分需要的公式。
- 公式参数统一维护，跨语言回归检查面板值与搜索结果一致；不保留 JS 搜索回退。
- 纯计算引擎显式接收具名参数，不在编译时包含生成数据。
- TS 管理基础装备、缓存、筛选、排序和翻页；日常浏览不触发 IPC。
- 普通属性评估不走 IPC；优化请求携带准备好的候选、上限、约束、食物和评分参数整包。
- Rust 不读取装备目录，也不负责编辑器文档、候选过滤或结果应用。
- 数据加载、Tauri 调度、计算、用户方案持久化有明确边界。
- 前端持有草稿，异步响应带 revision 与数据版本，过期结果不可应用。
- 支持有界并发、取消、精确 GCD/不慢于目标、锁定和独立优化范围。
- 仅完成精确搜索时声明最优；缺失规则、不可达和搜索超限明确提示。
- TS 校验和解释版本化方案 JSON；Rust 仅提供受限路径下的原子文件读写，文件仍在 `gearsets/`。
- 旧草稿先迁移再写入，失败不删除原数据；无效或缺失装备可替换恢复。
- 保存失败必须可重试；替换、批量清理、应用优化可以撤销。

## 分享与验收

- 保留 base62 网页协议，不加入自定义前缀、方案名或锁定字段。
- 分享直接复制编码；提示将编码通过 `?` 添加到任意兼容配装器的网址后。
- 支持粘贴编码或完整链接；无效编码、缺失装备和不可表达配置不得覆盖当前方案。
- 原 51 候选学者 780–795、GCD 2.40：速度 1237，期望 128.48722，食物 49244。
- 新数据允许产生更优结果；幻境 795 的 447/108 和骑士分配保持不变。
- 覆盖原生小规模穷举、约束、取消，目录原子更新，保存/恢复，分享往返，异步过期响应。
- 界面覆盖主题、窄窗口、长名称、2/3/5 孔、键盘与失败状态。
- 前端相关文件提交前运行 Prettier，Rust 提交前运行 rustfmt。
- 完成逻辑和视觉验证后询问提交；按可审阅的功能或文件分批，不自动 push/merge。
