# ffxiv-gearing 迁移规范

本文规定配装功能的目标接入方式与验收标准。

## 1. 目标与首期范围

- 一次性迁入功能代码，迁入后由 OpenRisingStones 独立维护。
- 保留装备选择、筛选、镶嵌、食物、属性汇总、阈值、伤害期望、品级同步、自定义武器、最优搜索和分享等核心行为。
- 尽量保留原业务模块、命名、计算关系和操作链路；能直接复制的代码直接复用。
- 按宿主的 View、ViewModel、Model、Service 分工接入；重写范围以实际耦合为依据。
- 首期聚焦配装，不顺带改造招募、幻化、传送等现有业务。
- 后续维护以更新数据和参数为常态，假设公式结构和主要业务逻辑保持稳定。

## 2. 源码组织与复用

原仓库作为一次性代码来源及持续的数据来源，不作为运行或构建依赖。
不使用 Git submodule、指向原仓库的本地包依赖或整站嵌入。
主仓库检出后，无需原仓库即可安装、构建、测试和运行。

| 原仓库内容                               | 本仓库归属与处理                                          |
| ----------------------------------- | ------------------------------------------------- |
| `views/` 中的业务组件                     | `src/components/gearing/`，复用装备表格、镶嵌等交互，适配主题和样式作用域 |
| `stores/` 中的装备、魔晶石、食物模型及派生关系        | `src/models/gearing/`，保留业务划分和必要的 MobX 状态链路        |
| 工作区生命周期与操作编排                        | `src/viewmodels/useGearingWorkspaceViewModel.ts`  |
| 功能页面组合与导航                           | `src/views/GearingWorkspaceView.tsx`              |
| 存储、剪贴板、数据加载和 IPC                    | `src/services/gearing/`                           |
| `share.ts`、`utils/base62.ts` 等可复用逻辑 | 配装内部模块，保持原编码协议                                    |
| 生成数据与可变规则参数                         | `src/data/gearing/generated/`                     |
| Web Worker 执行的优化算法                  | `src-tauri/` 内的配装计算模块，迁移为 Rust                    |

- 不迁入独立网页入口、Service Worker、网站发布流程和原工程配置。
- 使用本仓库的 React 根节点、导航、主题、设置及构建入口，不新增独立配装应用工程。
- 依赖统一在根 `package.json` 管理；现有 Vite、TypeScript 配置仅做必要兼容调整。
- 配装模型由工作区显式创建和释放，不在模块导入时启动全局 Store、计时器或历史监听。
- 浏览器历史、全局主题和持久化由宿主管理，配装业务模型不直接操作这些全局资源。
- 保留来源提交、许可证和复制代码的归属说明；完成迁移时补齐实际文件映射。

## 3. 状态管理边界

- 首期不将本仓库现有业务模块迁移到 MobX。
- 配装可以保留原实现所需的 MobX/MobX-State-Tree 依赖，使用范围限制在配装内部。
- 配装通过明确的 ViewModel 接口接入，现有业务不直接引用配装 Store。
- MobX 观察组件不得被不兼容的自动 memoization 改变响应行为；兼容配置限制在配装范围。
- 不为未来可能使用 MobX 而提前新增通用 Store 框架。

后续候选仅列入评估：高级招募的筛选条件联动、幻化搜索的筛选派生和异步请求状态。
先确认是否存在重复状态、派生关系复杂或测试困难，再判断 MobX 是否能改善这些问题。
演进时选择一个边界清楚的模块试点，验证收益后决定是否扩大，不预先承诺全仓迁移。

## 4. 数据与参数契约

“主要更新数据”指可变内容，不限于原仓库的 `data/` 目录。

| 类别   | 典型来源                                  | 更新方式           |
| ---- | ------------------------------------- | -------------- |
| 内容数据 | `data/out/` 的装备、食物、适用职业、属性上限、同步表、物品索引 | 自动导入           |
| 规则参数 | `game.ts` 的等级、职业、种族、魔晶石参数，以及公式中的可变系数  | 按提取清单自动导入      |
| 配置规则 | 自定义武器分配、装备来源分类、兑换成本、互斥配置              | 提取为声明式数据后导入    |
| 执行逻辑 | 运算结构、取整顺序、状态流转、搜索和剪枝过程                | 本仓库维护，不随数据导入覆盖 |

- 首次迁移将公式中的可变参数与运算逻辑分离，避免将参数写死在 Rust 或组件中。
- 提取清单记录源文件、符号或表达式位置、目标字段和校验方式，覆盖目录外的参数。
- 前端和 Rust 使用同一版本的数据与参数包，禁止分别维护两套数值。
- 数据包记录格式版本、游戏版本、来源提交、输入内容摘要、提取器版本和参数版本。
- 来源有未提交修改时记录该状态及实际内容摘要；提交号不能代替内容校验。
- 保留装备 ID、槽位、HQ、历史装备和引用关系的语义，避免数据更新破坏已有方案。
- 原产物中的稀疏数组、缺失值及特殊数值必须按明确规则转换，不用文本替换冒充格式解析。

## 5. 本地数据导入脚本

约定命令：

```bash
node scripts/import-gearing-data.mjs --source /path/to/ffxiv-gearing
node scripts/import-gearing-data.mjs --source /path/to/ffxiv-gearing --check
```

首次数据接入与后续更新使用同一命令；功能代码迁移是一次性工程，不由该脚本重复覆盖。

执行流程：

1. 检查来源目录、生成产物、数据与参数提取清单。
2. 在临时目录生成完整数据包，不执行源工程入口或任意源码。
3. 校验结构、唯一 ID、索引引用、职业与槽位、属性上限、魔晶石及公式参数。
4. 输出新增、修改、删除的数据数量，以及参数变化和兼容性检查结果。
5. 全部通过后整体替换生成目录；失败时原数据保持不变。

约束：

- `--check` 只校验并预览差异，不修改目标文件。
- 默认读取来源已有的生成产物；缺失时提示先在来源仓库完成数据生成。
- 不自动拉取仓库、联网下载、安装依赖、修改来源文件或发布应用。
- 同一输入产生相同输出，重复执行不产生无意义的差异。
- 仅管理生成目录及其清单；不写组件、模型、Rust 算法或用户保存的方案。
- 未知结构、必要参数缺失、引用失效或计算结构改变时停止导入并报告具体位置。
- 生成目录纳入版本管理，可整体回退；本机绝对来源路径不写入提交产物。
- 导入后重新构建应用即可使用新数据；首期不实现客户端在线数据更新。

## 6. Rust 计算与 IPC

- Rust 是优化搜索的唯一生产实现，不保留原 Web Worker 搜索实现、运行对照框架或 JavaScript 搜索回退。
- 前端保留轻量属性派生及展示；一次完整优化通过异步 IPC 提交，不按候选装备逐项跨 IPC 调用。
- 请求携带完整计算快照与数据、参数版本，结果只应用于仍匹配的当前请求。
- Rust 在后台线程计算，支持取消、并发限制和明确的搜索超限结果；离开工作区时取消任务。
- 覆盖原有速度范围、预算、戒指互斥、自定义武器联动、镶嵌限制等约束。
- 保留公式取整顺序及并列结果选择规则；不能将启发式结果标为最优解。
- 正确性使用固定输入与预期结果、小规模可穷举案例和约束检查验证，不依赖保留原算法。
- 性能验收使用 Rust release 构建，记录代表性输入规模、计算耗时及 IPC 总耗时。
- 非桌面运行环境明确提示优化不可用，不静默切回 Web Worker。
- 支持可以取消计算任务，前端也要加一个入口

## 7. 桌面保存与分享

- 当前配装支持本地保存与恢复，存储由宿主 Service 管理；不依赖网页历史条目保存草稿。
- 分享直接复制与原仓库协议一致的 base62 分享码，不新增前缀、封装或自定义编码。
- 复用原编码与解码逻辑，保持职业、等级、同步、装备、魔晶石和自定义属性等支持字段的语义。
- 分享操作不复制 `localhost`、Tauri 内部地址或本机文件路径。
- 复制成功后显示以下提示：

> 分享码已复制。将分享码添加到任意部署了 ffxiv-gearing 的网址后面，用“?”分隔，即可通过网页分享。

链接形式：`<配装器网址>?<base62分享码>`。目标网站需要支持对应的编码版本和装备数据。
本应用支持粘贴分享码或完整分享链接导入；链接只提取编码内容，不依赖打开网页。
无效编码、不支持的版本或缺失装备应明确提示，失败时不覆盖当前配装。
首期不新增分享服务器、配装文件交换协议或自定义桌面协议。

## 8. 验收与交付

- 四个主页入口及现有业务可正常使用，配装直接进入宿主工作区。
- 核心功能清单逐项验收，装备选择、镶嵌、同步、计算与结果应用形成完整操作链路。
- 返回首页、再次进入及重启应用后可恢复配装；主题和设置不影响其他模块。
- base62 编解码往返一致，与原协议的固定样例兼容；导入失败不丢失当前方案。
- 数据脚本覆盖首次导入、重复导入、参数更新、校验失败不写入和数据回退。
- Rust 覆盖最优值、合法性、并列选择、取消及超限；数据更新后运行相关计算回归。
- 提交前格式化相关前端文件，并对全部新增或修改的 Rust 文件执行 `rustfmt`。
- 交付包含本规范、来源及许可证说明、实际文件映射、导入脚本与验证记录。
- 按独立功能拆分提交，并遵守仓库的提交规模限制及人工确认要求。
