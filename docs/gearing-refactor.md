# 配装模块重构规范

本规范替代旧迁移规范中关于保留 MST、前端计算和 JSON 分组加载的要求。
其余来源许可、独立数据更新、CSS、分享兼容及提交要求继续有效。

## 目标与边界

- 以可保存的配装方案为中心，保留全部计算与配装能力。
- 只改配装及必要的数据生成、IPC、构建接入，不改其他业务与全局导航。
- 沿用 DESIGN.md 的深靛蓝、克制金色、共享 token 和原生 CSS。
- 不引入上游工程、submodule、本地导入入口、JS 求解回退或数据热重载框架。

## 数据流

```text
固定提交的原始表 + 本仓配置 → 校验/转换 → catalog.json
TS 加载/缓存装备 → 本地筛选、排序、翻页、查找
TS 属性计算/方案组装 → 数值输入整包 → IPC → Rust 优化搜索
TS 用户方案校验/恢复 → IPC → 不解释业务字段的 JSON 文件读写
```

- 基础装备和规则由 TS 从一个静态 JSON 资源加载、索引并缓存，不编译成装备 JS。
- 搜索、职业/部位/品级/来源筛选、排序、翻页、物品查找在 TS 内存完成，不调用 IPC。
- 最优搜索时一次传入 TS 准备好的候选、属性上限、镶嵌约束、食物和评分参数；Rust 只使用请求内存。
- Rust 不接收编辑器方案文档，不负责候选查询、方案组装或结果应用；普通属性预览不调用 IPC。
- 优化候选由独立的优化条件生成，不能只发送当前浏览页或被浏览筛选截断的数据。
- 原始 CSV、生成 JSON 和压缩快照均不提交；不再生成 SQLite。
- 更新仍用 gearing:data:update，保留来源摘要、版本、差异报告与原子安装。
- 数据版本与用户文档格式版本分开，更新目录不能覆盖方案。
- 物品定义、装备配置、方案、优化条件、UI 状态及派生结果分别建模。
- 内部使用正物品 ID 和明确槽位；左右戒指、食物、药品不复用负数语义。
- 来源和武器系列使用稳定 ID；公式参数具名，默认配置仅在生成时展开。
- 保存用户选择和已编辑备用配置，不保存候选缓存与派生值。

## 计算与状态

- TS 负责属性、HQ、镶嵌上限、同步、自定义属性、阈值、期望、用量统计和方案编排。
- Rust 负责组合搜索、剪枝、搜索约束和评分所需数学公式，保留输入校验与取消。
- React 持有唯一可编辑草稿，Rust 接收不可变快照，不维护第二份草稿。
- IPC 只传求解器所需的数值输入与共享参数，不传整份编辑器状态；结果由 TS 转回方案并计算比较信息。
- 面板公式和搜索评分共用同一份具名参数；跨语言回归校验取整与最终效果一致，不保留 JS 搜索回退。
- 引擎注入类型化参数，不依赖编译时数据文件或全局参数包。
- ViewModel 分别管理方案编辑、候选查询、优化任务，不新增全仓 Store。
- 每次计算关联草稿 revision 与数据版本；过期响应与结果不可应用。
- 保留有界并发与取消，区分不可达、超限、取消、无效输入和成功。
- 只有完成精确搜索的结果可标为最优，不伪造百分比或称期望为 DPS。

## 界面与关键交互

工作模式为 Operate：优先完成装备选择、比较和优化应用。
视觉特征是固定槽位的当前配装始终可见，候选与差异围绕当前槽位展开。

```text
方案/职业/同步/保存状态                      导入 分享
当前配装             当前槽位候选              属性/比较/优化
固定槽位顺序         筛选与排序                当前值 → 预览值
装备/魔晶石锁        装备与相关属性            明确的应用操作
```

- 宽窗口三栏；中等窗口两栏与详情抽屉；窄窗口切换任务区域。
- 不压缩文字硬塞三栏，不产生整页横向滚动；表格可在有标签的区域内滚动。
- 两、三、五孔使用固定轨道，区分保证孔与禁断，HQ 使用次要标记。
- 浏览筛选与优化范围独立；切换搜索不改变参与优化的装备。
- 锁装备与锁魔晶石是两种独立约束。

替换装备：选槽位 → 查看候选 → 选择并预览属性差异 → 替换/Enter → 可撤销。
预览不改变保存方案；替换、批量清理和优化应用均作为单次撤销操作。

优化应用：设置目标 → 范围与锁定 → 计算（可取消）→ 比较变化 → 应用或另存。
明确精确 GCD 与不慢于目标；生产/采集使用各自的三维目标。
结果显示目标达成、装备/魔晶石变更及规则缺项，失败时保留原方案。

## 兼容与恢复

- base62 维持原协议，旧约定只存在于编码适配层。
- 分享码复制后提示添加到部署配装器的网址后，用 `?` 分隔。
- 方案名、锁定等不写入旧编码；无法表达的配置明确阻止分享或要求修正。
- 先迁移旧 localStorage/MST 草稿，写入成功前不清除原数据。
- 缺失物品、不支持字段和损坏文档提供恢复提示，不静默丢弃。
- 方案结构及校验由 TS 管理，版本化 JSON 与目录资源分开；Rust 仅执行受限路径下的原子文件读写，失败有可重试状态。

## 实施顺序与验收

1. 数据、领域契约、TS 属性计算与 Rust 参数注入，保持原生搜索回归。
2. 方案编辑器、候选比较、锁定、撤销、多方案及保存。
3. 优化交互、迁移与分享、移除旧链路、完整回归与视觉验收。

- 原 51 候选学者 780–795/GCD 2.40：速度 1237、期望 128.48722、食物 49244。
- 当前全量候选允许改进结果；保留幻境 795 的 447/108 与骑士分配。
- 保留小规模穷举、戒指互斥、预算、联动、自定义、生产、DET/DHT 测试。
- 测试覆盖首次生成、更新失败不写入、保存恢复、过期响应和分享往返。
- 构建不得产生装备数据 JS 分块，编辑过程中不能阻塞界面。
- 检查深浅主题、长名称、窄窗口、2/3/5 孔、键盘、加载/失败/取消状态。
- 真实 Windows 验证若未执行须明确记录，不以 Mac 测试替代。
- 前端 Prettier、Rust rustfmt；完成后询问分批提交，不自动 push/merge。
